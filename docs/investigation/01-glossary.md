## 2. Naming conventions per layer

| Layer                | Case                                                   | Example                                          | Source of truth                                   |
| -------------------- | ------------------------------------------------------ | ------------------------------------------------ | ------------------------------------------------- |
| Postgres DB          | `snake_case`, plural tables                            | `sale_items.unit_price`, `debts.original_amount` | TypeORM entity `@Column({ name: '…' })`           |
| API / TypeORM entity | `camelCase` properties → mapped to snake_case columns  | `SaleItem.unitPrice` → `unit_price`              | `apps/api/src/entities/*.entity.ts`               |
| Shared types         | `camelCase` interfaces + `PascalCase` enums            | `interface Sale`, `enum PaymentMethod`           | `packages/types/src/*.types.ts`                   |
| SQLite (desktop)     | `snake_case` columns; timestamps are **TEXT ISO-8601** | `sale_date TEXT`, `sold_at TEXT`                 | `packages/electron-core/src/migrations/00xx_*.ts` |
| Local desktop model  | `PascalCase` `Local*` types                            | `LocalSale`, `LocalContact`, `LocalSaleItem`     | `apps/desktop-v2/src/main/services/*.service.ts`  |

**Mapping layer:** there is **no separate mapper**. DB↔TS coercion is done by TypeORM column transformers (`decimalTransformer` → JS `number`, `dateTransformer` → JS `Date`, `apps/api/src/common/entities/transformers.ts`). The desktop sync engine maps snake_case columns to camelCase via ~20 hand-written maps (`SALE_MAP`, `DEBT_MAP`, … `packages/electron-core/src/services/sync.service.ts:139-398`).

## 3. IDs, timestamps, soft-delete, enums

- **ID strategy** — UUID everywhere, **consistent**. Server: `@PrimaryGeneratedColumn('uuid')` on `BaseEntity`/`ImmutableBaseEntity`. Desktop: **client-generated** `randomUUID()` (node `crypto`, e.g. `contacts.service.ts:186`); the same UUID is used for the local row and its `sync_outbox` payload so client and server agree. **No ULID, no autoincrement.** (Specs 01/02 propose ULID for sortability — that would be a _new_ convention; the house style is UUID v4.)
- **Timestamps** — Postgres `timestamptz` via `@CreateDateColumn`/`@UpdateDateColumn`/`@DeleteDateColumn` on `BaseEntity` (`base.entity.ts:14-21`), columns `created_at`/`updated_at`/`deleted_at`. SQLite stores **TEXT ISO-8601 strings** (not epoch numbers). **All timestamps are UTC**; there is no business timezone. `sale_date` is a stored `date`/`YYYY-MM-DD` = UTC calendar day of `soldAt`.
- **Soft delete** — `deletedAt`/`deleted_at` via `@DeleteDateColumn` on the mutable `BaseEntity`. `ImmutableBaseEntity` (logs/movements/payments) has no soft delete — id + `createdAt` only. Some entities also carry an `isActive`/`is_active` flag, but the delete convention is `deletedAt`. Desktop SQLite uses an `is_deleted` column.
- **Enum storage** — TS string-constant enums stored as `varchar`. No integer codes, no lookup tables. Cross-app enums live in `packages/types` (`PaymentMethod`, `SubscriptionPlan`, `Resource`, `DebtStatus`, …); entity-local enums (e.g. `MovementType`) are declared inline in the entity file. **Audit `AuditAction`/`AuditActorType` are TS unions, NOT DB enums** — freely widenable without migration.

## 6. Stale prior-memory corrections (verified this pass)

- `SyncEntity` is **27 entities**, not 11 (`sync.types.ts:19-45`).
- `plan-access.ts` (client permission mirror) **no longer exists** — it belonged to the removed v1 `apps/desktop`. desktop-v2 has no local Resource gate; the real gate is server-side + at the sync push boundary.
- `Role` entity has **no `tracksCashDrawer` / `systemKey`** field — those were a design decision never implemented (`role.entity.ts`).
- Toolchain is **pnpm@11.9.0 / Node ≥22.13.0** (root `package.json`), not 9.15.0 / ≥20.
- There is **no `lastCostPrice` field**; valuation uses `product.cost_price` (current stored cost).
